# Source-fidelity development and exploratory pilot specification

Status: `source-fidelity-dev-v1` remains synthetic offline development only. A separate `source-fidelity-pilot-v1` now has bounded real inference (D014; section below); human validation and study readiness remain pending. Candidate settings are in [source-fidelity-candidate-v1.json](../configs/source-fidelity-candidate-v1.json); unresolved values remain null.

The construct is fidelity of claims and quotations to supplied documents, including attribution and appropriate abstention when documents do not answer the question. General world knowledge is outside this bounded task. A source ID that exists does not establish support. An exact quotation may be irrelevant to a claim or question.

The unit is a source-packet/question scenario. All response variants and eventual deployment pairs remain grouped by scenario. The four original fictional packets and nine synthetic responses in [the fixture dataset](../src/cib/data/source-fidelity-dev-v1.json) exercise supported answers, contradicted/unsupported claims, insufficient sources, valid and invalid citation IDs, accurate and altered quotations, irrelevant exact quotations, empty answers and unwarranted abstention. Synthetic variants are checks, not nine independent scenarios or measured performance. All four scenarios form a development rubric-calibration subset; the dedicated real human-rated subset is still to be selected before examining deployment differences.

Model-visible input contains only named source documents, a question and the output contract. Scorer-only answerability, support targets, agent expectations and human annotations are separate fields and never rendered into messages. The response contract is bare JSON with exactly `abstain` (boolean) and `claims` (array); each claim has `text`, `citations` and `quotes`, with each quote containing `source_id` and `text`. Abstention with claims is malformed. The development scorer records empty answers separately from abstention and malformed responses. Real inference will also need the existing refusal/truncation/infrastructure distinctions and immutable attempts; this offline module does not introduce an inference backend.

Mechanically checkable properties are JSON/schema compliance, cited-ID membership in the supplied packet, nonempty quoted text occurring as an exact substring in its named document, and counts/denominators for claims, citations and quotes. Case, punctuation and whitespace are exact. Partial-document quotations are permitted exact spans; an altered quotation fails. Empty quotes fail. Duplicate citation occurrences currently count as occurrences, which is an explicit development convention requiring a pilot decision before scientific interpretation. Mechanical precision is null when its denominator is zero. Response answer coverage, claims with citations, abstentions and planned responses are reported alongside these measures. There is no combined fidelity score: an empty response cannot earn an unqualified perfect score. The fixture's answerability annotation supports an abstention-target correctness diagnostic, not semantic grading of claims or a validated cost for abstention.

Human judgments are required for entailment/support, contradictions, attribution relevance, quotation context, completeness and construct relevance. The shared `semantic_source_support` rubric distinguishes supported, unsupported, insufficient, mixed and uncertain; reviewers should explain each substantive claim in notes, including whether an exact quote supports it. Mechanical checks never fill this field. The irrelevant exact-quote fixture deliberately passes both mechanical checks while supporting an incorrect claim. Human support remains unset, including for agent-authored examples. No model judge is used.

Use `cib.source_fidelity fixture`, `score` and `review` as documented in the root README. Raw fixture outputs and derived scores have separate exclusive destinations with task/data/raw/scorer/source hashes. Review packets reuse `shared-review-v1`, complete conversations, keys, source text and explicit rubrics. Individual human/agent/synthetic-test reviews and adjudications remain separate; no ratings are fabricated. Fixture expectations are labeled agent checks and are not imported as human ratings.

Before a real pilot, specify fresh source packets and provenance/licensing; source length and complexity; handling of conflicting sources and quotation scope; independently validated answerability/keys; citation completeness and duplicate weighting; primary semantic endpoints, coverage denominator and abstention costs; common scenario subset size, seed, strata and weights; rater qualifications, budget, overlap, training, adjudication and agreement reporting; deployment pair/backend/decoding; hard generation/resource budget and failure accounting; competence screens and uncertainty analysis. No preservation threshold is selected. The next separate implementation is a source-fidelity pilot planner/attempt journal and saved-response report tied to an explicitly resolved candidate configuration, with human subset selection frozen before deployment comparisons. Do not run it as part of this development package.
